## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| event history to feature snapshot | The `as_of_ts` cut is where a future fact can silently become a past one; every downstream model metric depends on this cut being honest |
| simulator ground truth to feature inputs | The import contract governs code; the file system does not, so the data path needs its own boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-25 | Repudiation | Temporal leakage producing inflated, unfalsifiable model results | high | mitigate | Point-in-time correctness is delegated to DuckDB's purpose-built ASOF join rather than a hand-rolled latest-row loop; the boundary predicate is inclusive and documented; and `tests/leakage/test_no_lookahead.py` asserts the property over the entire materialized grid rather than on a sample, with violating rows named on failure. QUALITY_BAR classes skipping this as unacceptable debt. |
| T-01-26 | Information Disclosure | Feature transforms reading the simulator ground-truth zone | high | mitigate | Two independent checks in `tests/leakage/test_ground_truth_isolation.py`: a static `ast` walk over every feature module, and a dynamic recording of every zone the path resolver is asked for during a real `materialize_grid` run. Either alone could be evaded; together they cover both the literal-path and the computed-path route. |
| T-01-27 | Tampering | A random split reintroduced by a future contributor | medium | mitigate | `splits.py` exposes no shuffle, seed or proportion parameter, and a repository-wide import walk fails the suite if any random-shuffling splitter is imported under `src/` or `tests/`. Residual: a contributor could hand-roll one, which code review must catch. |
