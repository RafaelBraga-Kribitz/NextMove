## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-28 | Repudiation | Golden determinism test that cannot detect divergence | high | mitigate | The suite asserts both halves: equal seeds produce identical digests AND a changed seed produces at least one differing digest. A test asserting only equality would pass for a pipeline that ignores its seeds entirely. Runs are additionally launched under differing `PYTHONHASHSEED` values and working directories so environment-dependent ordering cannot hide. |
| T-01-29 | Tampering | Golden fixture regenerated to make a failing test pass | high | mitigate | The recorded prohibition in this plan's `must_haves.prohibitions` states that a golden update must be an explicit, separately-committed change with its cause stated. No recipe or CLI flag regenerates goldens in place, so a regeneration is necessarily a visible diff in review rather than a side effect of running the suite. |
| T-01-30 | Denial of Service | Interrupted pipeline leaving the workspace in a half-written state | medium | mitigate | Every table is written to a temporary path and atomically renamed by plan 01-06's storage layer; this plan's golden suite proves it by killing a run mid-ingest and asserting neither a partial table nor a leftover temporary file remains in `data/canonical/` or `data/lineage/`, then that a clean rerun still reproduces the expected digests. |
| T-01-33 | Tampering | Overlapping DVC stage outputs silently destroying another stage's artifacts | high | mitigate | Lineage is one fragment per stage in its own zone (plan 01-06), so every declared out belongs to exactly one stage. Two independent checks enforce it: a static script loads `dvc.yaml` and fails if any stage's outs path equals or contains another stage's outs or deps path, and the golden suite re-runs one stage alone and asserts the other stages' fragments are byte-unchanged. Without this, `ingest` re-materializing `data/canonical/` would erase the lineage rows `simulate` wrote, and `dvc.lock` would churn on every run — making phase success criterion 1 undemonstrable. |
