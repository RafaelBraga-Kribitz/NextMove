<objective>
Define the one canonical event schema the whole project is built on (DATA-01) and the inward-only
adapter seam that keeps it canonical.

Purpose: TECHNICAL_DIRECTION section 2 is contracts-first, and every later stage — quarantine,
lineage, features, decisions — keys off this shape. Getting the identity, timezone and ordering
semantics right here is what makes byte-identical reruns and point-in-time correctness achievable
later; getting them wrong is only discovered when a golden test fails three plans downstream.
Output: `Event`, its typed payload union, the deterministic id derivation, and the `IngestAdapter`
registry that the v2 public-clickstream track (D-13) plugs into without touching core code.
</objective>

| producer to canonical store | Every record crossing into the store passes through `Event` validation; this is the project's only input-validation surface in Phase 1 |
| external record shape to canonical schema | Adapter conversion is where an untrusted external vocabulary is translated; the direction of that translation is a design-integrity property |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-11 | Tampering | `Event` / payload validation | high | mitigate | Strict Pydantic validation with `extra="forbid"` on every payload model, a discriminated union so an unknown `type` cannot fall through to a permissive generic payload, a cross-field validator asserting `payload.type` matches the top-level `type`, and integer-only monetary fields so no value can be coerced through a lossy float path. Malformed rows are rejected rather than coerced; plan 01-09 routes them to quarantine (D-20). |
| T-01-12 | Repudiation | Non-deterministic `event_id` generation | high | mitigate | `derive_event_id` is a `uuid5` over the event's own identifying tuple, and the acceptance criteria assert no random UUID generator appears in the module. A random identifier would make ENG-04's byte-identical claim unattainable and turn a published reproducibility guarantee into a false statement. |
| T-01-13 | Tampering | Reverse (outward) mapping added to the adapter seam | low | mitigate | The `IngestAdapter` protocol declares only an inward method; acceptance criteria assert no outward converter exists. Accepted residual: a determined contributor can still add one, but they cannot do it accidentally or by convenience. |
</threat_model>
