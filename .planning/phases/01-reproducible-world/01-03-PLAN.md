    - `deep_merge(base, overlay)` returns overlay values per key and recurses into nested dicts
    - `deep_merge` does not mutate either argument
    - An overlay that restates a base value byte-for-byte yields a merged dict equal to the base
    - An empty overlay yields the base unchanged and an identical `config_hash`
    - Two logically identical configs whose YAML files list keys in different orders hash identically
    - `load_config("nonexistent")` raises an error whose message contains the string `nonexistent`
    - An overlay introducing an undeclared key raises `ValidationError` naming that key
    - `config_hash` returns a 64-character lowercase hex sha256 digest
  </behavior>
  <action>
    Create `src/nextmove/config/loader.py` exposing four names.

    `deep_merge(base: dict, overlay: dict) -> dict` — pure recursive merge where the overlay wins
    per key and two dicts merge recursively; returns a new dict and mutates neither input. This is
    deliberately hand-written rather than imported (RESEARCH "Don't Hand-Roll": the semantics must
    match D-23's "override only what differs" exactly, and the function is small enough to be fully
    tested in-repo).

    `ResolvedConfig` — a frozen dataclass with fields `config: Config`, `config_hash: str`,
    `profile: str`, and `source_files: tuple[Path, ...]`.

    `load_config(profile: str, config_dir: Path | None = None) -> ResolvedConfig` — reads the eight
    per-domain base files in a fixed declared order defined as a module-level constant
    `BASE_DOMAIN_FILES` (simulator, features, data_quality, constraints, actions, mcda, experiments,
    autonomy), merging each under its own top-level key so domain files cannot collide; then reads
    `config_dir / "profiles" / f"{profile}.yaml"` and deep-merges it over the accumulated base. Parse
    every file with PyYAML's safe loader (`yaml.safe_load`) and never the default full loader —
    the full loader can instantiate arbitrary Python objects from a config file. A file that parses
    to `None` (empty or comments-only) is treated as `{}`. A missing profile file raises
    `FileNotFoundError` whose message contains the requested profile name and the list of available
    profile names. Resolve `config_dir` to an absolute path and assert the resolved profile path is
    inside it, so a profile argument such as a relative traversal sequence cannot read a file
    outside the config tree. Finally set the `profile` key on the merged dict and call
    `Config.model_validate(merged)`.

    `config_hash(config: Config) -> str` — canonicalizes with
    `json.dumps(config.model_dump(mode="json"), sort_keys=True, separators=(",", ":"))` and returns
    `hashlib.sha256(...).hexdigest()`. `sort_keys=True` is what makes YAML key order irrelevant;
    `mode="json"` is what gives dates and enums one stable string form. Document in the docstring
    that no wall-clock value may ever enter the hashed surface.

    Create `tests/unit/test_config_merge_hash.py` covering every item in the `behavior` block above
    using inline YAML written into `tmp_path` (do not depend on the repository's real config tree —
    Task 3 owns that). Include an explicit test that a config dict whose keys are inserted in
    reverse order produces the same hash as the forward-order dict.
  </action>
