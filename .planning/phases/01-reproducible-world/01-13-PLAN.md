<objective>
Close UAT gap G-01-2: the Linux CI "Memory budget suite" step does not execute the peak-process-RSS
assertions it exists to enforce. Two independent, stacked bugs
(.planning/debug/ci-budget-marker-mismatch.md):

Bug A — the step and the Justfile `budget` recipe both filter with `-m slow`, but across the three
budget files only `test_default_profile_completes_within_its_stated_budget` carries that marker. The
three `test_demo_subprocess_peak_rss_under_budget` tests the UAT item names carry no marker at all, so
`-m slow` deselected them and the step collected exactly one unrelated test.

Bug B — that one collected test asserts wall clock before peak RSS, and its demo-profile wall-clock
budget (600.0s) is tighter than CI hardware delivers (638.4s observed), so the AssertionError fired
before `measure_subprocess_peak_rss()` was ever called. Independent of Bug A.

Secondary masking effect — GitHub Actions' default `bash -eo pipefail` plus the step's own
`set -o pipefail` means pytest's non-zero exit aborts the script before the step's own
`if grep ... skipped` gate runs, so the gate that is the whole point of the step has never executed.

Purpose: ENG-08's memory bound is the one claim in this phase that has been declared five times
(plans 01-06, 01-08, 01-09, 01-10, 01-11) and measured zero times, because every contributing plan ran
on a Windows machine where the assertion self-skips. Linux CI is the enforcing platform (D-16) and its
gate is currently inert.

Output: a dedicated `peak_rss` marker carrying exactly the RSS-dependent assertions, a CI step that
selects them and cannot pass while any of them skips or silently disappears, a Justfile recipe that
reproduces the same selection locally, and a fast unit test that catches marker/filter drift on the
dev machine instead of on the next quarterly CI run.
</objective>
